# План переработки сайта dantist45.ru

Исходные материалы:
- действующий сайт https://dantist45.ru (главная, `/services`, футер);
- старый репозиторий https://github.com/Chetson/dantist45 (Next.js 16.1 + SQLite/better-sqlite3, админка услуг/категорий/объявлений);
- документы: «Контролирующие органы_Сайт.docx», «Врачи_7 мкр.docx», «Врачи_2 мкр.docx», скан лицензии ЛО-45-01-001150 от 28.01.2014 и «Приложение к лицензии.pdf» (приложение № 1, адрес мкр. 2, 9/III);
- стек нового проекта — см. [spec.md](spec.md) (Next.js 16.4 App Router, Cache Components, Tailwind v4, PostgreSQL + Prisma, Docker).

---

## 1. Ключевые принципы

1. **Никаких форм.** На сайте нет форм обратной связи, записи, «перезвоним», подписок, комментариев и отзывов. Связь только по телефону и при личном визите (ссылки `tel:`, адрес, карта-ссылка). Сайт не собирает персональные данные посетителей.
2. **Весь изменяемый контент — из БД:** услуги и цены, врачи, филиалы, уведомления, лицензии, контролирующие органы, документы. Код меняется только при изменении вёрстки.
3. **Мультифилиальность заложена с первого дня:** сущность «Клиника/филиал», к которой привязаны адреса, часы работы, телефоны, сотрудники, лицензионные приложения и (опционально) уведомления. Добавление третьего филиала — запись в БД, а не правка кода.
4. **Соответствие обязательным требованиям к сайту медорганизации** (раздел 9): данные юрлица, лицензия, перечень услуг и цены, сведения о медработниках, режим работы, контакты контролирующих органов.
5. **Сначала публичная часть, потом админка.** На этапе 1 данные заводятся через seed-скрипт Prisma; схема БД сразу проектируется под будущую админку (флаги публикации, сортировка, показ на главной).

## 2. Карта сайта (структура страниц)

```
/                                  Главная (лендинг)
/services                          Услуги и цены (все категории + таблицы цен)
/services/[slug]                   Описание отдельной услуги/направления + её цены
/specialists                       Все специалисты (фильтр по филиалу и должности)
/specialists/[slug]                (опционально) Карточка специалиста: образование, аккредитации
/clinics                           Филиалы: адреса, часы работы, телефоны, как добраться
/clinics/[slug]                    Страница филиала: адрес, режим, сотрудники филиала, лицензионное приложение
/licenses                          Лицензии: реквизиты, виды работ, сканы (лицензия + приложения по адресам)
/regulators                        Контролирующие органы: названия, адреса, телефоны, сайты, часы приёма
/documents                         Информация для пациентов: нормативные документы, образцы договоров, правила
/legal                             Сведения о юрлице (реквизиты, ОГРН/ИНН, руководитель) — можно совместить с футером
/privacy                           Политика обработки персональных данных (см. 9.3)
/admin/...                         Админка — этап 2, вне публичной навигации
```

Главное меню: **Услуги и цены · Специалисты · Филиалы · Лицензии · Контролирующие органы · Пациентам**.
Футер: реквизиты юрлица, адреса и телефоны филиалов, краткий блок контролирующих органов со ссылкой на `/regulators`, ссылки на лицензии, документы и политику, обязательный дисклеймер.

## 4. Блок «Важные уведомления»

Сейчас: одна HTML-строка `announcement_html` + флаг `announcement_active` в таблице `settings`, выводится через `dangerouslySetInnerHTML` без санитизации.

Новое решение — **отдельная таблица `Announcement`, несколько уведомлений одновременно**:

- поля: заголовок, текст (Markdown или санитизированный HTML), уровень важности (`info` / `warning` / `critical` → цвет и иконка), `isActive`, `startsAt` / `endsAt` (график на праздники сам появится и сам исчезнет), `sortOrder`, привязка к филиалам (пусто = для всех; иначе показываем пометку «Филиал мкр. 2»);
- на главной — список активных уведомлений под Hero; длинные уведомления сворачиваются («Подробнее»);
- опционально: тонкая полоса-уведомление `critical` во всех страницах над header (например, «Филиал временно закрыт»);
- рендер: Markdown → HTML на сервере + санитизация (например, `sanitize-html` / `rehype-sanitize`), никакого «сырого» HTML от редактора;
- кэширование: `'use cache'` + `cacheTag('announcements')` + `cacheLife` порядка минут (чтобы срабатывали `startsAt`/`endsAt`); при правке в админке — `revalidateTag('announcements')`.

### Структура карточки

- ФИО, фото (необязательно), должности по филиалам, специализации;
- **Образование и квалификация** — список документов: тип (диплом / диплом о переподготовке / удостоверение ПК / сертификат / свидетельство об аккредитации), номер, дата, организация, специальность/квалификация. Хранить структурированно (таблица `StaffDocument`), а не одним текстом — проще валидировать и красиво выводить.

### Страница `/specialists`

Все опубликованные сотрудники (`isPublished`), группировка «Врачи» / «Средний медперсонал», фильтр по филиалу. Медсёстры и рентгенолаборанты тоже выводятся — сведения о медработниках, участвующих в оказании платных услуг, обязательны (9.1).

### Виджет на главной

Настройка `SiteSettings.doctorsWidgetMode`:

| Режим | Поведение |
|---|---|
| `HIDDEN` | Виджет не выводится вообще |
| `AUTO` | Первые 6 опубликованных врачей по `sortOrder` |
| `SELECTED` | Только сотрудники с галочкой `showOnHome` (по `sortOrder`, максимум 6) |

Плюс `isPublished` на каждом сотруднике — скрывает его и с главной, и со страницы специалистов. Все три переключателя появятся в админке на этапе 2; до этого — через seed.

- Штаченко О.В. и Ситяева К.М. — номер аккредитации не заполнен (`№ ______`).
- Филиппова Н.М. — у обоих свидетельств об аккредитации нет даты.
- Фото и любые данные сверх обязательных (образование/квалификация) публиковать только с письменного согласия сотрудника на распространение ПДн (ст. 10.1 152-ФЗ).

## 6. Услуги и цены

### Структура

- `ServiceCategory` — направление (Терапия, Хирургия, Ортопедия, Гигиена, Консультации, Подарочные сертификаты…): название, `slug`, краткое описание, иконка, `sortOrder`, `isPublished`, `showOnHome`.
- `ServiceArticle` — описательная статья (Удаление ультразвуком, Air Flow, Бюгельное протезирование, Acry-Free…): `slug`, заголовок, текст (Markdown), изображение, привязка к категории. Выводится на `/services/[slug]` вместе с таблицей цен своей категории.
- `Service` — строка прайса: название, **код по номенклатуре медицинских услуг** (Приказ Минздрава № 804н — по желанию, но удобно), цена **числом** (`priceFrom`, опционально `priceTo` для «от … до …»), единица (`за зуб`, `за челюсть`…), примечание, `sortOrder`, `isPublished`.

Сейчас цена хранится текстом — отсюда баг «2 000 ₽ублей» на сайте. Цена будет `Decimal`/`Int` (рубли), форматирование — `Intl.NumberFormat('ru-RU', { style: 'currency', currency: 'RUB' })`.

### Страница `/services`

- шапка с навигацией-якорями по категориям;
- для каждой категории — краткое описание + таблица «Наименование · Стоимость»; на мобильных таблица превращается в список карточек;
- над/под прайсом обязательная пометка: цены не являются публичной офертой, актуальность — у администраторов; дата последнего обновления прайса (`max(updatedAt)`);
- поиск по услугам — клиентский фильтр по названию (прайс небольшой; TanStack Virtual понадобится, только если позиций будут тысячи).

### Открытые вопросы

- Цены **одинаковые во всех филиалах** или различаются? Если различаются — добавить таблицу `ServicePrice(serviceId, clinicId, price)` и переключатель филиала на странице. Схема ниже допускает это расширение без миграции данных.
- Какие услуги оказываются в каком филиале (например, ортодонтия — только по лицензии конкретного адреса, см. 7).

### Чего не хватает

- С 2021 г. лицензии ведутся в виде записей в едином реестре (бумажные бланки больше не выдаются), поэтому рекомендуется добавить актуальную **выписку из реестра лицензий** и ссылку на запись в реестре Росздравнадзора — там отражены все текущие адреса и работы, включая изменения после 2014 г.

### Страница `/licenses`

Для каждой лицензии: номер, дата, кем выдана, вид деятельности, ссылка на реестр; ниже — **приложения по адресам**, каждое с перечнем работ (текстом — чтобы индексировалось и читалось скринридерами) и привязкой к `Clinic`. Сканы — превью (`next/image`) + открытие в полном размере (лайтбокс) + скачивание PDF.
На странице филиала `/clinics/[slug]` выводится его приложение к лицензии.

Хранение файлов: на этапе 1 — `public/licenses/*` (webp для превью + pdf оригинала), на этапе 2 — загрузка из админки в volume/объектное хранилище.

## 8. Контролирующие органы и документы для пациентов

### `/regulators`

Карточка органа: полное название, короткое название, адрес, телефоны (в т.ч. горячая линия), email, сайт, часы приёма, чем занимается (одной строкой: «качество и безопасность медицинской помощи», «защита прав потребителей», «лицензирование и региональный контроль»). Плюс вводный текст: куда обращаться, если пациент считает свои права нарушенными; сначала — к руководству клиники (контакты заведующего).

По документу:

1. Территориальный орган **Росздравнадзора** по Курганской области.
2. Управление **Роспотребнадзора** по Курганской области.
3. **Департамент здравоохранения** Курганской области.

Контакты сейчас в футере сайта (ул. Ленина 5 оф. 501; ул. Куйбышева 46; ул. Томина 49 и телефоны) — **перед публикацией перепроверить по официальным сайтам органов**, плюс добавить федеральные горячие линии Росздравнадзора и Роспотребнадзора.

### `/documents` («Пациентам»)

Группы (таблица `Document` с полем `group`):

- **Нормативные документы:** 323-ФЗ «Об основах охраны здоровья граждан в РФ»; Закон РФ № 2300-1 «О защите прав потребителей»; Правила предоставления платных медицинских услуг; Территориальная программа госгарантий Курганской области.
- **Договоры:** договор платных услуг, договор на ортодонтическое лечение (PDF).
- **Прочее:** правила внутреннего распорядка для пациентов, политика обработки ПДн, информация о программе госгарантий (как получить бесплатную помощь).

Ссылки на нормативные акты — на официальные источники (pravo.gov.ru / КонсультантПлюс / Гарант), а не копии текста.

**Устаревшее в документе — заменить:**
- ПП РФ от 04.10.2012 № 1006 **утратило силу** с 01.09.2023 → действующие Правила утверждены **ПП РФ от 11.05.2023 № 736**.
- Территориальная программа «на 2017 год и плановый период 2018–2019» (ПП Курганской обл. № 451 от 30.12.2016) → нужна **действующая программа на текущий год** (её реквизиты лучше вынести в БД, чтобы обновлять ежегодно).

## 9. Юридические требования

### 9.1. Обязательная информация на сайте (ПП РФ № 736, ст. 79 323-ФЗ)

Чек-лист — каждый пункт должен быть на сайте:

- [ ] полное и сокращённое наименование, адрес юрлица и адреса мест оказания помощи, ОГРН, ИНН (футер + `/legal`);
- [ ] сведения о лицензии (номер, дата, перечень работ, орган) — `/licenses`;
- [ ] перечень платных услуг с ценами — `/services`;
- [ ] порядок и условия оказания услуг, образцы договоров — `/documents`;
- [ ] сведения о медработниках: образование и квалификация — `/specialists`;
- [ ] режим работы каждого филиала и график работы специалистов — `/clinics`;
- [ ] адреса и телефоны органа здравоохранения субъекта, Росздравнадзора и Роспотребнадзора — `/regulators` + футер;
- [ ] информация о программе госгарантий бесплатной медпомощи — `/documents`.

### 9.2. Отсутствие форм

Никаких `<form>`, `input`, чатов-виджетов, онлайн-записи и сторонних виджетов обратного звонка. Контакт — только `tel:` и личный визит. Это и есть основная мера по 152-ФЗ.

Исключение — админка `/admin`: формы там заполняют сотрудники клиники, страницы закрыты входом и не индексируются; данные посетителей сайта она не собирает.

### 9.3. Скрытый сбор ПДн (cookies, аналитика, сторонние скрипты)

Даже без форм сайт может «собирать ПДн» через сторонние сервисы (Роскомнадзор относит cookie и IP к ПДн):
- **Яндекс Метрика / Google Analytics** — не подключать, либо подключать только с баннером согласия на cookie и политикой;
- **встроенные карты** (iframe Яндекс/2ГИС) — ставят свои cookie: заменить на статичную картинку/ссылку «Открыть в 2ГИС / Яндекс Картах»;
- **шрифты** — только через `next/font` (самохостинг), без запросов к fonts.googleapis.com из браузера;
- кнопки VK/TG — простые ссылки, без виджетов.

Если всё это соблюдено, cookie-баннер не нужен. Политика обработки ПДн всё равно желательна: клиника — оператор ПДн пациентов, а на сайте публикуются ПДн сотрудников (ФИО, образование, фото).

### 9.4. Реклама медицинских услуг (38-ФЗ «О рекламе», ст. 24)

- обязательная пометка «**Имеются противопоказания, необходима консультация специалиста**» — в футере и на страницах услуг;
- **нельзя** публиковать отзывы/благодарности пациентов и ссылки на конкретные случаи излечения → блок отзывов убираем;
- **нельзя** гарантировать результат → убираем «100% гарантия», «Пожизненная гарантия», «совсем не больно»;
- рекламировать можно только то, что входит в лицензию → убрать «Лечение во сне» (нет анестезиологии), «Ортодонтия» — только если вид работ есть в приложении к лицензии мкр. 7.

## 11. Технические решения

- **Рендер:** публичные страницы — Server Components; данные читаются функциями в `lib/data/*.ts` с `'use cache'` + `cacheTag(...)` (`services`, `staff`, `announcements`, `clinics`, `licenses`, `regulators`). Админка инвалидирует через `revalidateTag`. Сверять API с `node_modules/next/dist/docs/` (Cache Components включены — без `Suspense`/`use cache` сборка упадёт).
- **TanStack Query / Virtual** (из spec.md) на публичном сайте не нужны — объёмы маленькие, данные отдаются сервером. Оставить их для админки (таблицы прайса, сотрудников).
- **БД:** PostgreSQL в Docker + Prisma (миграции, seed из документов). Переносим данные из SQLite старого сайта: категории и услуги (с конвертацией цены из текста в число) — разовый скрипт `scripts/migrate-from-sqlite.ts`.
- **Seed** (`prisma/seed.ts`): организация, 2 филиала, сотрудники с документами из docx, лицензия + приложение, 3 органа, документы, текущие уведомления (праздничный график, «официальные источники»).
- **SEO:** `generateMetadata` на каждой странице, `sitemap.ts`, `robots.ts` (закрыть `/admin`), JSON-LD `Dentist`/`MedicalClinic` на каждый филиал (адрес, часы, телефон), `MedicalOrganization` для юрлица.
- **Доступность:** семантическая разметка, контраст, таблицы цен с `<th scope>`, alt у сканов, навигация с клавиатуры, крупный шрифт для пожилых пациентов.
- **Что не переносить из старого репо:**
  - cookie `auth` с JSON `{userId}` без подписи — подделывается вручную; `/api/*` (users, services, settings) вообще не защищены `proxy.ts` (matcher только `/admin`) → в новой админке: подписанная/серверная сессия, проверка роли в каждом Server Action / Route Handler;
  - `dangerouslySetInnerHTML` с HTML из редактора без санитизации;
  - цены строкой, захардкоженный фейковый телефон `+7 (3522) 12-34-56` и «перезвоним в течение 15 минут» на `/services`.
