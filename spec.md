# Спецификация проекта

Документ описывает технологии и подходы, которые используются в проекте.

## Стек

| Область | Технология |
|---|---|
| Фреймворк | Next.js 16 (App Router), React 19 |
| Язык | TypeScript (strict) |
| Стили | Tailwind CSS v4 |
| База данных | PostgreSQL |
| ORM | Prisma |
| Инфраструктура БД | Docker (Dockerfile / docker-compose) |
| Клиентское состояние и запросы | TanStack Query |
| Виртуализация списков | TanStack Virtual |

## База данных: PostgreSQL

- Используется PostgreSQL как основная СУБД.
- БД разворачивается локально в Docker-контейнере. Dockerfile (и при необходимости `docker-compose.yml`) в проекте ещё **не создан** — это одна из ближайших задач.
- Параметры подключения хранятся в переменных окружения (`.env.local`, не коммитится; пример — `.env.example`), например `DATABASE_URL`.
- Данные хранятся в именованном Docker volume, чтобы переживать пересоздание контейнера.
- Доступ к БД выполняется только на сервере (Server Components, Route Handlers, Server Actions). Клиент к БД напрямую не обращается.
- Для работы с БД используется Prisma ORM: схема описывается в `prisma/schema.prisma`, типобезопасный Prisma Client используется для запросов.
- Миграции схемы создаются через Prisma Migrate (`prisma migrate dev` локально, `prisma migrate deploy` в окружениях) и версионируются в репозитории.
- Prisma Client создаётся единым экземпляром (singleton) в серверном модуле, чтобы не плодить соединения при hot reload в dev.

### План по Docker

1. Создать `Dockerfile` / `docker-compose.yml` с сервисом `postgres`.
2. Пробросить порт, задать пользователя, пароль и имя БД через переменные окружения.
3. Добавить volume для данных и healthcheck.
4. Описать запуск в README / CLAUDE.md (`docker compose up -d`).

## Клиентское состояние: TanStack Query

- TanStack Query используется для работы с данными, приходящими с сервера (запросы, кэш, инвалидация, мутации), и для локального клиентского состояния, связанного с этими данными.
- `QueryClientProvider` подключается в клиентском компоненте-обёртке, которая используется в `app/layout.tsx`.
- Ключи запросов централизованы (фабрики query keys) для предсказуемой инвалидации.
- Мутации используют оптимистичные обновления там, где это уместно.
- Начальные данные можно получать на сервере и передавать через гидратацию (`HydrationBoundary`), чтобы избежать лишних загрузок на клиенте.

## Виртуализация списков: TanStack Virtual

- Для больших списков используется `@tanstack/react-virtual`: в DOM рендерятся только видимые элементы.
- Совместно с TanStack Query применяется бесконечная подгрузка (`useInfiniteQuery`): следующая страница запрашивается при приближении к концу списка.
- Виртуализированные компоненты — клиентские (`"use client"`).

## Особенности Next.js в проекте

- Включены `cacheComponents` и `partialPrefetching`: динамический доступ к данным оборачивается в `Suspense` либо кэшируется через `use cache`, иначе сборка падает.
- Перед написанием кода сверяться с документацией в `node_modules/next/dist/docs/`.
- Алиас путей: `@/*` → корень репозитория.

## Общие подходы

- Серверные компоненты по умолчанию; `"use client"` — только там, где нужна интерактивность (TanStack Query, TanStack Virtual).
- Строгая типизация, без `any`.
- Линтинг через `npm run lint` (ESLint flat config).
- Секреты и параметры окружения не коммитятся.
